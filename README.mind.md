# Mind

## 心得

- 心得
  - 説明できないものは理解できていない
  - わからないまま進めない。理解せずに進んではいけないものを見極める。読み飛ばさない
  - 分からない時は比較する。並べる。ケースを洗い出す
  - 全てに理由が必要。なぜそうなるか、そうするか

- 姿勢
  - それを見て自分だったらわかりやすいか? を自問自答する。
  - レビュアーがどうのの前に自分としては。でまずは考える。

- 効率性
  - 忘れる前に記憶カードに追記する。記憶カードは詳しく書かない  

- 計画性
  - TODOを確認し随時修正する
  - 1日の見通しを見積もる
  - かかった時間を記録する
  - 次の目標を言語化する。それが30分であっても

- 技術
  - エラーメッセージはちゃんと読む
  - 可読性の向上（先例に習った上で、パフォーマンスも意識する）
  - 小さいプロジェクトを作り整理する。不具合再現にも活用。

- メモ
  - 直感は重要。一旦立ち止まることが重要

## ベストプラクティス

- 1ファイル1コンセプト
- 業務ルールはコンポーネントの外へ出す
  - Angular、React、CLIでも、バックエンドでも意味がある → Component外
- パフォーマンス特化制約がある場合はその旨記載する

## テスト設計の記載粒度

- 実施項目:
  - 大: 何をしたいか: ・・・の算出に必要な情報が不足している場合、または・・・が不要な場合に。・・・・が登録されないことを確認する
  - 中:   その中で簡単に分類すると: ・・・状態
  - 小:     それを詳しく: ・・・の場合で、（さらに）・・・の場合、・・・になる確認
- 確認項目:
  - アウトプットとなる記載をする
